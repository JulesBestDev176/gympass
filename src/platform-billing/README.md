# Platform gym billing

This ledger records what gyms pay GymPass, separately from member payments and GymBro subscriptions. No online charge or external message is triggered. Prices and issuer information are entered through GymDash → Abonnements salles → Paramètres. The initial monthly price is undefined; existing gyms have no billing account and remain accessible until explicitly enabled or an invoice is issued.

`GET /api/v1/platform-billing/overview` and all billing commands require an active ADMIN JWT, `x-gymdash-secret`, and an email in the comma-separated `GYMDASH_BILLING_ADMIN_EMAILS` server setting. The same verified administrator restriction now applies to legacy GymDash control routes through GymDashGuard. A gym owner's ADMIN role alone grants no platform billing access. No configured administrators means denied access.

Calendar-month payments preserve the cycle's original UTC day through short months. Renewals append to paidUntil while active, otherwise start when payment is recorded. Backdated paidAt is journal metadata; it does not silently backdate coverage. Partial payments do not grant time. Grace (default7days, configurable0–90) applies immediately to existing deadlines when changed. At grace expiry, protected gym operations return402, including existing JWT sessions. Account security endpoints and verified platform management remain available for renewal. Billing never rewrites the manual Gym.statut. Standalone GymBro users have no gym billing account.

Invoices snapshot identities and prices at issue. Monthly-price changes affect future invoices. Paid invoices are not edited/deleted; only completely unpaid invoices can be cancelled with a reason. Partial payments, balance validation, invoice numbering, idempotency commands and coverage updates run in serializable transactions with bounded conflict retries. UUID command keys deduplicate exact retries and reject a changed payload. A timeout is ambiguous: retry with the same command. UI retains unresolved commands per tab across reloads until success or deliberate editing. Cancellation leaves no amount due in its PDF.

The migration `20261017090000_platform_billing` only creates the six new tables/enum, indexes and restrictive foreign keys. It creates no invoice, payment or account. Run `prisma migrate deploy`; never reset or db-push a production database. Root rollout captured a successful private local PostgreSQL backup before deploying.
